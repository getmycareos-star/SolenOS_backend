# SolenOS

A trust-first living care record.

## Philosophy

SolenOS is built on the belief that in healthcare, trust is the feature. Every product decision should strengthen:
- Trust
- Evidence
- Transparency
- Uncertainty handling
- Continuity
- Accuracy
- Explainability
- Reliability

See `docs/philosophy.md` for the full product philosophy.

## Architecture

- **Backend**: FastAPI + SQLAlchemy (Python)
- **Frontend**: React + Vite (TypeScript)
- **Database**: SQLite for local development; production requires managed PostgreSQL (for example, Supabase). Production startup rejects SQLite and missing database configuration.

## Getting Started

### Backend
```bash
cd backend
pip install -e .
uvicorn app.main:app --reload
```

### Frontend
```bash
cd frontend
npm install
npm run dev
```

## Principles

1. **Trust Over Features** - Every capability must strengthen trust, continuity, evidence, transparency, or cognitive load reduction.
2. **Evidence Over Intelligence** - Every insight links back to its source.
3. **Transparency Over Hidden Reasoning** - Show known, possible, and unknown clearly.
4. **Uncertainty Is a Feature** - Never hide what is not known.
5. **Calm Over Clever** - Reduce caregiver anxiety, don't impress.
6. **Build for the Worst Day** - Hospital discharges, late-night confusion, exhaustion.


## Production configuration

Configure these as backend service environment variables (for Railway, use the backend service's Variables panel). Never commit secret values or expose them to the frontend.

- `DATABASE_URL`: Supabase PostgreSQL connection URL. Use the database connection string, not a browser-facing URL.
- `SECRET_KEY`: a unique random value of at least 32 characters.
- `SUPABASE_URL`: the Supabase project URL.
- `SUPABASE_SERVICE_ROLE_KEY`: the private service-role key; backend only.
- `SUPABASE_STORAGE_BUCKET`: the name of a **private** Supabase Storage bucket, for example `care-evidence`.

The caregiver photo-upload endpoint remains unavailable until all three Supabase Storage variables are configured and the private bucket exists. The backend stores an opaque object path in the evidence record and creates short-lived signed viewing URLs; it does not store uploaded photos on Railway's ephemeral filesystem. Rotate any database password that has been exposed and update `DATABASE_URL` with the new value.

## Confidence-score migration

Change, pattern, pattern-derived situation, reasoning-memory and temporal-record confidence is **unknown** until a calibrated scoring method exists. Before deploying the Phase 4 backend changes to an existing PostgreSQL database, apply `backend/migrations/20261023_unknown_pattern_confidence.sql` once with the database migration operator. It makes the affected columns nullable and clears historical scores generated by uncalibrated formulas. Do not deploy the changed backend against an unmigrated database.
